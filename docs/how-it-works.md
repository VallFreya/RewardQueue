# Как это работает

## Откуда берутся записи

Плагин входит в Twitch по коду (Device Code Flow, публичное приложение, без секрета) и подписывается на событие «заказ награды за баллы канала» (EventSub, WebSocket). Каждый заказ выбранной награды становится записью очереди: название награды, ник зрителя, его сообщение, время заказа. Записи идут строго по времени заказа, одинаковые заказы не схлопываются.

Дубликаты отсекаются по id заказа. Если соединение оборвалось, плагин переподключается сам, но заказы за время обрыва Twitch не повторяет.

Записи можно добавлять и вручную: кнопка «Добавить» в шапке очереди раскрывает форму над списком этой очереди. Название награды выбирается из наград очереди или пишется своё, ник и сообщение необязательны.

## Очередь на диске

Очередь хранится в `queue.json` рядом с `config.json` и записывается при каждом изменении атомарно. Если файл не удалось прочитать, он сохраняется рядом как `queue.json.broken`. Выполненные и убранные записи удаляются сразу, невыполненные старше трёх дней удаляются при запуске и раз в час.

## «Делаю»

Кнопка «Делаю» поднимает запись на первое место её очереди и помечает как выполняемую. В очереди такая запись одна: порядок остальных не меняется, прежняя выполняемая запись остаётся второй без пометки. «Вернуть в очередь» снимает пометку и возвращает запись на место по времени заказа. Новые заказы не встают перед выполняемой записью.

## Несколько очередей

Каждая отмеченная награда относится ровно к одной очереди (по умолчанию к первой). Награды перетаскиваются между очередями, очереди меняются местами за ручку. Записи переезжают вслед за наградой. Удалить можно любую очередь, кроме последней: её награды и записи уходят в первую очередь. У каждой очереди свои «Сейчас», нумерация с 1, необязательное название и лимит «Показывать до N».

«Показывать до N» у очереди и «Показывать всего записей» для всех очередей действуют только на трансляции (в оверлее), 0 означает без ограничения. В доке всегда видны все записи; когда очередей несколько, в каждой видны минимум три записи, остальные прокручиваются внутри очереди.

## Что показывает оверлей

Ширина блока равна размеру источника «Браузер». Очереди идут стопкой. Внутри очереди записи идут по порядку сверху вниз и показываются, пока запись целиком помещается по высоте; на первой запись, которая не поместилась, очередь останавливается (следующие не показываются, даже короткие). Следующая очередь при этом показывается, если для неё есть место. Название очереди без записей не показывается. Если не помещается самая первая запись на экране, она показывается обрезанной с многоточием на последней влезающей строке.

Название награды на трансляции не пишется: только ник и сообщение (название показывается у записи, у которой нет ни ника, ни сообщения). Запись «Сейчас» показывается крупной карточкой и в лимиты не входит.

## Защита локального сервера

Страницы отдаёт небольшой HTTP-сервер на `127.0.0.1`. В адресе случайный ключ, он хранится в `config.json` и не меняется между запусками. Сервер проверяет ключ, заголовок `Host`, а для запросов не-GET и `Origin`. Обновления идут на страницы через SSE, команды страниц отправляются POST-ом.

## config.json

Папка: `%APPDATA%\obs-studio\plugin_config\RewardQueue`. Большая часть настроек меняется в окне, несколько полей только в файле (редактировать при закрытом OBS):

| Поле | Что делает |
|---|---|
| `theme` | Тема окна настроек: `dark` или `light` |
| `port` | Порт локального сервера (по умолчанию 47615). После смены нужно заново вставить адреса в OBS |
| `access_key` | Ключ в адресах. Чтобы выпустить новый, удалите значение: ключ создастся при следующем запуске, адреса в OBS придётся вставить заново |
| `retention_days` | Сколько дней хранится невыполненная запись (по умолчанию 3, не больше 30) |
| `client_id` | Свой Client ID приложения Twitch вместо встроенного (обычно пусто) |
